SCOPE · APPROVED

Go Frog Go

An endless top-down pixel-art road-crossing game, played by a fast decision model with a slow LLM coaching it.

THE KERNEL

You can watch System 2 teach System 1 from nothing. Jev makes every hop, starting with one instruction: "jump forward." After each death, Nemotron writes a lesson, and Jev plays the next run with the whole playbook. (Revised in PRD: no mid-run takeover.)

HOW ONE RUN FLOWS

WHO IT'S FOR

Developers who saw Jev (or models like it) and want to see what a "System One" model is good for once a reasoning LLM is directing it. Also Matt, who wants to learn exactly that.

WHY IT MATTERS

"That's my whole point."

Matt came to learn Jev and how it works with an LLM controlling it. It runs on Jev through Vercel AI Gateway.

WHAT "WORKING" LOOKS LIKE

A few runs back to back. Run 1 hops straight into the first car. A lesson appears. Run 2 waits at that same kind of lane and gets farther. A later run goes much farther.

The "oh, that's cool" beat: the frog surviving the exact thing that killed it last time, because of a lesson you watched get written.

LOOK & FEEL

Crossy Road's endless lanes and stepped hopping, with Frogger's close calls. Top-down pixel art and arcade nostalgia. Sparked by a video of Jev playing Super Mario Bros. and Smash in real time. Original name and sprites, nothing borrowed. crossyroad.com

BOUNDARY

Now: the proof of concept
  • One endless level: road lanes, cars at varied speeds
  • Top-down pixel-art rendering in the browser
  • Jev as System 1 through a swappable adapter (one file to swap)
  • Playbook starts as "jump forward"
  • Nemotron on Nebius Token Factory as System 2: one lesson after each death, never a mid-run move
  • On screen: playbook, confidence readout, distance per run
Later
  • Race Jev against another System One model
  • Rivers, logs and trains
  • Hosted demo URL, open-source license and polish for Nebius (due Oct 30, after Basics closes Oct 26)
  • Human vs. AI mode
  • Sound
Cut, and why
  • Coach taking over mid-run (would rescue early runs and hide the learning-from-nothing story)
  • Real Mario, Smash, Crossy Road or Tetris assets or names (third-party IP, which both hackathons forbid)
  • Raspberry Pi, LEDs and RFID (LEDs alone don't sense anything, and the RFID ideas didn't land)
  • The earlier code-scanner idea (Matt wanted something fun to watch)
  • Reading game state from pixels (the game hands Jev its state directly)
